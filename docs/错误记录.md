# Aurora 错误记录(踩坑台账)

> **目的:犯过的错不重复犯。**
> **铁律一:任何 agent 犯错(报错、误操作、返工)后,必须在此追加一条记录并提交 git。**
> **铁律二:新 agent 开工前必读本文件,连同 [开发进度.md](./开发进度.md)。**

## 记录格式

```
| 日期 | 错误 | 根因 | 教训/防再犯 |
```

## 错误记录

| 日期 | 错误 | 根因 | 教训/防再犯 |
|---|---|---|---|
| 2026-08-11 | `git push -c http.proxy= ...` 报 usage 帮助 | `-c` 配置项必须放在子命令**之前**:`git -c http.proxy= push ...`,放后面被当作 push 选项 | 写命令前确认参数位置;报 usage 说明参数解析失败 |
| 2026-08-11 | 按旧记忆"绕代理直连"执行 push 超时失败 | 网络状况是变量:这次直连 github.com 不通,走 127.0.0.1:7897 代理才通 | **网络状况以实测为准**;先试直连,不通立刻试代理 7897,不要纠结 |
| 2026-08-11 | 首次 push 被拒(远端有本地没有的提交) | 在 GitHub 网页建仓库时默认勾选了 LICENSE/README,GitHub 自动生成了 initial commit | 新建远程仓库后先 `git fetch` 看远端内容,再 `pull --rebase` 合并;LICENSE 内容相同会被自动跳过 |
| 2026-08-11 | 项目名连续更名两次(nexus→atlas→aurora),文档全局替换返工 | 名字没定稿就动手替换,用户随后改主意 | **命名/方向类决策先跟用户确认到定稿再全局替换**;替换用 sed 全量改是快的,但每次返工都浪费时间 |
| 2026-08-11 | 建库时远端自动生成的文件与本地内容冲突(同上) | 本地先写了 LICENSE,远端也生成了 LICENSE | 建库选择"不要自动添加 README/license/.gitignore",或先建空库再推 |

## 已知环境坑(避免重踩)

| 坑 | 说明 |
|---|---|
| git 代理 | 全局代理 127.0.0.1:7897 时开时关。**每次先试直连,不通走代理**,两条都试再报网络问题 |
| Windows 盘加密策略 | Claude 直接读 Windows 盘(C:/D:)上的截图/图片会无法解码。需要看图时,请用户重新截一张发来;自己渲染的产物写到 WSL 原生盘再读回 |
| PowerShell 管道喂 WSL | 管道会加 CRLF 导致 WSL 命令整行报错;驱动 WSL 用 heredoc(LF 干净) |
| git 提交规范 | 中文 commit message;上传 GitHub 的内容不留 AI 痕迹(无 Co-Authored-By 等署名) |

## 协作纪律(多 agent 通用)

- 状态变了(环境、配置、文件)立即更新 [开发进度.md](./开发进度.md) 并提交;
- 犯了上面没有的新错 → 按格式追加本文件;
- 引用本项目之外的经验时,以本机实测为准,不要照搬记忆。
