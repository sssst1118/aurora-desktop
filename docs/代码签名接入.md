# Aurora Desktop Windows 代码签名接入指南

适用范围:Aurora Desktop 桌面应用(仓库 `D:\github\show`,Tauri 2 + Rust)。本文介绍 Windows 代码签名的背景、证书选择、具体操作、Tauri 集成与 CI 接入方式。

---

## 1. 背景:为什么需要签名

### 1.1 发布与更新机制

应用使用自研 updater(未引入 `tauri-plugin-updater`),发布流如下:

1. 服务器放置 `latest.json`(含 `version` / `sha256` / `download_url`)+ NSIS 安装包;
2. 客户端从设置页手动检查更新,或每 6 小时自动检查;
3. 客户端对版本做语义化比较,并做 SHA-256 校验,校验通过后下载;
4. 下载完成后通过 `cmd /C start /wait` 静默执行 NSIS 安装包(`/S` 参数),随后退出应用;
5. 更新包缓存目录为 `%LOCALAPPDATA%\Aurora\updates`。

应用默认安装到用户目录(`installMode: currentUser`),自动更新按用户级安装设计,**全程无需管理员权限**。

### 1.2 SmartScreen 与发布者身份

Windows 对未签名的安装包在运行时会有提示:

- **未签名**:SmartScreen 会提示「Windows 已保护你的电脑」,发布者显示为「未知发布者」,用户需要点击「更多信息 → 仍要运行」才能继续,体验较差,也容易让用户怀疑软件来源;
- **已签名(受信任证书)**:SmartScreen 能显示发布者名称(如 "Aurora Desktop"),提示弱化为普通确认,信任度明显提升;
- **签名 + 良好信誉**:Windows 10/11 下部分用户甚至不会看到 SmartScreen 拦截(取决于应用信誉积累)。

### 1.3 现状:未签名可用,签名是可选项

当前发布包**未签名**,软件本身可以正常安装使用,自动更新也完全不受影响——因为 updater **不依赖签名,没有签名校验逻辑**。

签名属于「预留接入」:它只用于消除 SmartScreen 的「未知发布者」提示、向用户展示发布者身份,接不接签名都不影响自动更新的工作流程。**建议在对外正式发布时接入签名,但不阻塞当前迭代。**

## 2. 签名对象清单

| 产物 | 路径 | 是否需要签名 | 说明 |
| --- | --- | --- | --- |
| NSIS 安装包 | `src-tauri/target/release/bundle/nsis/*.exe` | **必须** | 自动更新实际下载、静默安装的目标格式(支持 `/S` 静默),是签名优先级最高的对象 |
| MSI 安装包 | `src-tauri/target/release/bundle/msi/*.msi` | 必须 | 与 NSIS 一同发布;MSI 不支持静默自动安装,自动更新不经过它,但既然对外发布,也应签名 |
| 主程序 exe(内嵌资源) | `src-tauri/target/release/aurora.exe` 等 | 可选 | 签名后可显示文件属性中的数字签名信息;不影响自动更新,可按需处理 |

打包产物由 `pkg tauri build` 生成,输出到 `src-tauri/target/release/bundle/{msi,nsis}`。**自动更新走 NSIS**(支持 `/S` 静默),MSI 不支持静默自动安装,所以发布给自动更新的文件只有 NSIS。

### 签名工具:signtool.exe

签名使用 Windows SDK 自带的 `signtool.exe`:

- 通常随 **Visual Studio Build Tools(勾选「使用 C++ 的桌面开发」或「Windows SDK」组件)** 一起安装;
- 默认位置形如 `C:\Program Files (x86)\Windows Kits\10\bin\<版本号>\x64\signtool.exe`;
- 在开发人员命令行(Developer Command Prompt)中可直接用 `where signtool` 查找;若 PATH 未配置,可手动定位到上述路径使用。

## 3. 证书类型:自签名 vs 受信任证书

| 类型 | 用途 | SmartScreen 效果 | 成本 |
| --- | --- | --- | --- |
| **自签名证书** | 开发测试、内部分发 | 依然提示「未知发布者」(根证书不受信任),仅能验证文件完整性 | 免费,本地生成 |
| **OV 代码签名证书** | 正式对外发布 | 可显示发布者名称;SmartScreen 信誉需随下载量、时间逐渐积累,新证书初期可能仍有提示 | 数百到上千元/年,需企业身份审核 |
| **EV 代码签名证书** | 正式对外发布(大厂首选) | 可较快获得 SmartScreen 即时信誉,提示大幅减少 | 最贵,需硬件令牌(USB Key)+ 严格审核 |

要点:

- 自签名证书**无法消除** SmartScreen 警告,只适合验证签名流程本身是否跑通(签名、验证、时间戳);
- 正式对外发布应购买**受信任 CA 的代码签名证书**;个人/小团队通常选 OV,追求发布体验选 EV;
- EV 证书签名要求使用硬件令牌,不可导出私钥,CI 接入方式与 OV 略有不同(见第 7 节)。

## 4. 具体操作步骤

以下命令在 Windows PowerShell(管理员或普通用户均可,currentUser 安装无需管理员)中执行。

### 4.1 生成自签名证书(仅测试用)

```powershell
# 生成代码签名自签名证书(一年有效)
$cert = New-SelfSignedCertificate -Type CodeSigningCert `
    -Subject "CN=Aurora Desktop Dev" `
    -CertStoreLocation Cert:\CurrentUser\My `
    -NotAfter (Get-Date).AddYears(1)

# 导出为 pfx(含私钥),需设置导出密码
$pwd = ConvertTo-SecureString -String "你的pfx密码" -Force -AsPlainText
Export-PfxCertificate -Cert $cert -FilePath .\aurora-dev.pfx -Password $pwd
```

> 正式证书请向 CA(如 DigiCert、Sectigo、GlobalSign 等)购买,拿到 pfx(或先用 `certutil` / `mmc` 从证书库导出 pfx)后直接进入 4.2。

### 4.2 使用 signtool 签名

```powershell
# 基本参数:/f 证书文件 /p 私钥密码 /fd SHA256 文件摘要算法
# /tr 时间戳服务器(RFC3161)/td SHA256 时间戳摘要算法
signtool sign /f .\aurora-dev.pfx /p 你的pfx密码 /fd SHA256 `
    /tr http://timestamp.digicert.com /td SHA256 `
    .\src-tauri\target\release\bundle\nsis\Aurora_0.1.0_x64-setup.exe
```

- 时间戳服务器也可用 `https://timestamp.digicert.com`(HTTPS 变体,适合 http 被劫持/禁用的环境);
- 务必加时间戳(`/tr`):这样即使日后证书过期,已经签名的旧包仍可正常验证(签名时间早于证书有效期)。

### 4.3 验证签名

```powershell
signtool verify /pa /v .\src-tauri\target\release\bundle\nsis\Aurora_0.1.0_x64-setup.exe
```

输出中应看到:

- 签名者信息(Subject 为证书主题);
- 时间戳信息(签名时打的时间戳);
- `Number of files successfully Verified: 1`。

## 5. 双签名注意:MSI 与 NSIS 都要签

- 每次发布,**MSI 与 NSIS 两个产物都要签名**(命令相同,只是目标文件不同);
- MSI 与 exe 使用相同的 `signtool sign` 命令,参数完全一致;
- **NSIS 安装包签名后,`/S` 静默安装行为不受任何影响**——签名只修改文件的 Authenticode 数据,不改变安装逻辑,自动更新链路(下载 → SHA-256 校验 → 静默安装)照常工作。

## 6. Tauri 集成建议

`tauri.conf.json` 目前**没有签名配置字段**,Tauri 2 打包本身不做签名,签名在打包完成后对产物文件执行即可。推荐在仓库中放一个签名脚本:

**scripts/sign.ps1**(对 bundle 目录下所有安装包循环签名,自动定位 signtool):

```powershell
# scripts/sign.ps1 - 对 tauri build 产物批量签名
# 用法:.\scripts\sign.ps1 -PfxPath .\aurora.pfx -PfxPassword "你的密码"
param(
    [Parameter(Mandatory = $true)]
    [string]$PfxPath,

    [Parameter(Mandatory = $true)]
    [string]$PfxPassword,

    [string]$TimestampUrl = "http://timestamp.digicert.com",

    [string]$BundleDir = "src-tauri/target/release/bundle"
)

$ErrorActionPreference = "Stop"

# 1. 定位 signtool.exe
$signtool = (Get-Command signtool.exe -ErrorAction SilentlyContinue).Source
if (-not $signtool) {
    # 常见安装位置兜底(含版本通配符)
    $roots = @("${env:ProgramFiles(x86)}\Windows Kits\10\bin", "${env:ProgramFiles}\Windows Kits\10\bin")
    $candidates = $roots | ForEach-Object {
        Get-ChildItem -Path $_ -Filter "signtool.exe" -Recurse -ErrorAction SilentlyContinue
    }
    $signtool = ($candidates | Sort-Object FullName -Descending | Select-Object -First 1).FullName
    if (-not $signtool) {
        throw "未找到 signtool.exe。请安装 Windows SDK(随 Visual Studio Build Tools 提供)。"
    }
}
Write-Host "使用 signtool: $signtool"

# 2. 收集待签名产物:NSIS(*.exe) + MSI(*.msi)
$files = @()
foreach ($sub in @("nsis", "msi")) {
    $dir = Join-Path $BundleDir $sub
    if (Test-Path $dir) {
        $files += Get-ChildItem -Path $dir -Include *.exe, *.msi -Recurse
    }
}
if ($files.Count -eq 0) {
    Write-Warning "bundle 目录下没有待签名产物,请先执行 pkg tauri build。"
    exit 1
}

# 3. 逐个签名并验证
foreach ($file in $files) {
    Write-Host "==> 签名: $($file.FullName)"
    & $signtool sign /f $PfxPath /p $PfxPassword /fd SHA256 /tr $TimestampUrl /td SHA256 $file.FullName
    if ($LASTEXITCODE -ne 0) { throw "签名失败: $($file.FullName)" }
    & $signtool verify /pa /v $file.FullName | Out-Null
    if ($LASTEXITCODE -ne 0) { throw "签名验证失败: $($file.FullName)" }
}

Write-Host ""
Write-Host "全部产物签名完成: $($files.Count) 个文件"
Write-Host "提醒:签名会改变文件哈希,latest.json 的 sha256 必须在签名之后再计算。"
```

使用方式:

```powershell
# 先打包
pkg tauri build
# 再签名
.\scripts\sign.ps1 -PfxPath .\aurora.pfx -PfxPassword "你的密码"
```

## 7. CI 自动化建议(GitHub Actions)

在 release 流程中加入签名步骤,简要流程如下:

1. **证书入 secrets**:将 pfx 转 base64 存入仓库 secret(如 `CODESIGN_PFX_B64`),密码存 `CODESIGN_PFX_PASSWORD`(私钥不进仓库、不进 git,见第 9 节);
2. **job 使用 windows-latest runner**,步骤:
   - `actions/checkout` + 安装 pnpm(Node.js setup);
   - `pnpm install --frozen-lockfile`;
   - 执行 `pnpm tauri build`(runner 有外网,WiX/NSIS 工具链会自动下载;如 runner 走代理,提前 `export HTTPS_PROXY=...` 即可);
   - **解密并还原 pfx**:

     ```powershell
     [IO.File]::WriteAllBytes(
       "cert.pfx",
       [Convert]::FromBase64String($env:CODESIGN_PFX_B64)
     )
     ```

   - **签名**:调用第 6 节的 `scripts/sign.ps1`(传 `-PfxPath cert.pfx -PfxPassword $env:CODESIGN_PFX_PASSWORD`),或直接 signtool 命令行;
   - **计算 sha256**(签名后!):

     ```powershell
     (Get-FileHash .\src-tauri\target\release\bundle\nsis\Aurora_*-setup.exe -Algorithm SHA256).Hash.ToLower()
     ```

   - **发布**:将 NSIS 包上传到自己的更新服务器(如 `scp`),把算好的 `sha256` 写进 `latest.json` 一并上传;若用 GitHub Releases,可借助 `softprops/action-gh-release` 附上安装包资产。

> EV 证书因私钥在硬件令牌中不可导出,CI 无法直接持有 pfx,通常需借助 Azure Trusted Signing 或专用签名服务器,OV 证书无此限制(可按上述 pfx + secrets 方案接入)。

## 8. 发布流程回顾

### 8.1 latest.json 结构

```json
{
  "version": "0.2.0",
  "sha256": "<NSIS 安装包签名后的 SHA-256 hex 小写>",
  "url": "https://你的服务器/updates/Aurora_0.2.0_x64-setup.exe"
}
```

字段说明:

- `version`:与 `src-tauri/tauri.conf.json` 的 `version` 一致,客户端做语义化版本比较;
- `sha256`:NSIS 安装包(`download_url` 指向的那个文件)的 SHA-256,十六进制小写,客户端下载后逐字节校验;
- `url`:NSIS 安装包的完整下载地址。

### 8.2 发布顺序(顺序很重要)

1. `pkg tauri build` 产出 MSI + NSIS;
2. 对产物**先签名**(第 4、5、6 节);
3. **签名后**再计算 NSIS 文件的 SHA-256,写入 `latest.json`;
4. 把 NSIS 安装包和 `latest.json` 一起上传到服务器;
5. 客户端检测到新版本 → 校验哈希 → 下载 → `/S` 静默安装。

> 签名会改变文件内容,因此哈希必须在签名之后计算。若把签名前的哈希写进 `latest.json`,客户端 SHA-256 校验会失败,更新会中断。

## 9. 注意事项

- **私钥安全**:pfx(含私钥)绝不能提交进 git,建议在 `.gitignore` 中加 `*.pfx`;本地妥善保管,CI 中一律走 secrets,日志中不得出现密码明文;
- **时间戳服务器网络可达**:签名时机器需能访问时间戳服务器(如 `http://timestamp.digicert.com`,端口 80/443);内网或代理环境要确保放行,否则 `/tr` 会失败导致整体签名失败;
- **证书过期与续期**:代码签名证书有效期通常 1–3 年,到期前需续期;已带时间戳的旧包在证书过期后仍可正常验证,但**新包必须用有效期内证书签名**,续期后重新跑一遍签名流程;
- **哈希顺序**:先签名、后计算 sha256、再写 `latest.json`(见 8.2);
- **构建网络要求**:WiX(MSI)/NSIS 工具链首次构建需要联网下载;代理环境下执行 `export HTTPS_PROXY=http://127.0.0.1:7897` 再构建;
- **静默安装兼容**:NSIS 签名后 `/S` 静默安装不受影响;应用为 `currentUser` 用户级安装,自动更新按用户级设计,无需管理员权限;
- **签名不影响更新逻辑**:updater 无签名校验,签名仅用于消除 SmartScreen「未知发布者」提示;即使某次发布漏签,自动更新依然可用,只是用户安装时提示较多——因此签名是发布质量项,不是功能依赖。
